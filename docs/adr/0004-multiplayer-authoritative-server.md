# ADR 0004: 멀티플레이 — 서버 권한형 + 엔진 없는 전용 서버

- 상태: 채택 (2026-11-24)

## 맥락
사용자 요청: 전투·경제 중심 **멀티플레이**. ARCHITECTURE의 "Phase 1 싱글, 멀티는 나중"을 바꾼다. 경제가 있으니 돈·아이템을 클라이언트가 결정하면 안 된다.

## 결정
1. **서버 권한형**. 클라이언트는 입력(`PlayerCommand`)만 보낸다. 피해·돈·아이템·의뢰 진행은 서버 코어가 결정.
2. **전용 서버 = 엔진 없는 .NET 프로세스**가 `Harbor.Core`를 호스팅. Godot은 클라이언트 표현 전용. (코어가 엔진 독립이라 공짜로 얻는 이점 — ADR 0002)
3. 코어에 `Net` 모듈 추가: 전송 포트 `ITransport`, 이진 메시지 직렬화, 서버 세션, 입력 버퍼, 스냅샷, **클라이언트 예측 + 보정**, **스냅샷 보간**, **랙 보정용 히스토리**.
4. 전송 구현은 포트 밖: 테스트는 `InMemoryTransport`(지연·손실 시뮬레이션), Godot 클라이언트는 ENet 어댑터, 전용 서버는 이후 UDP 라이브러리(도입 시 별도 ADR).
5. 틱 30Hz / 스냅샷 20Hz / 입력 매 틱(최근 3개 중복). 되감기 상한 350ms (왕복 250ms + 보간 100ms).
6. 결정적(deterministic) 이동 함수 하나(`Movement.Step`)를 서버와 클라 예측이 같이 쓴다 — 보정 오차를 최소화.
7. 경제는 이중 기입 원장 + 멱등 트랜잭션 ID (`Economy` 모듈, 서버에서만 실행).

## 결과
- 모든 게임 규칙이 CI(엔진 없음)에서 서버+클라 시뮬레이션 테스트로 검증된다.
- 싱글플레이 = 로컬 서버 + 클라 1명 (같은 경로, 분기 없음).
- 근거리 차량 물리는 Godot(Jolt)에 있으므로 운전자 클라이언트가 1차 권한, 서버는 타당성 검사만 (예외로 명시).
- 대가: 모든 상호작용이 커맨드/이벤트를 거쳐야 해서 기능 추가 시 메시지 정의가 필요하다.
